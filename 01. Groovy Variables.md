# Groovy Variables — Notes

## 1. What is a Variable?

A **variable** is a name used to store a value in a program.

For example:

```groovy
int age = 25
```

Here:

- `int` → data type
- `age` → variable name
- `25` → value

You can think of it like a labeled box:

```text
age
┌─────────┐
│   25    │
└─────────┘
```

The name `age` allows the program to access the value `25`.

### Simple example

```groovy
def name = "Ashraf"
println name
```

Output:

```text
Ashraf
```

---

# 2. Data Types in Groovy

Groovy supports the common Java data types.

Some important ones are:

| Data Type | Example | Used for |
|---|---|---|
| `byte` | `byte x = 10` | Small integers |
| `short` | `short x = 100` | Small integers |
| `int` | `int x = 1000` | Integers |
| `long` | `long x = 100000L` | Large integers |
| `float` | `float x = 10.5f` | Decimal numbers |
| `double` | `double x = 10.5` | Decimal numbers |
| `char` | `char x = 'A'` | Single character |
| `boolean` | `boolean x = true` | True/false |
| `String` | `String x = "Hello"` | Text |

Example:

```groovy
int age = 30
double salary = 50000.50
boolean isActive = true
String name = "Ashraf"
char grade = 'A'
```

# 3. Two Ways to Define Variables in Groovy

Groovy gives you two common approaches:

1. **Static typing**
2. **Dynamic typing**

---

# 4. Static Typing

With static typing, you explicitly specify the data type.

### Syntax

```groovy
dataType variableName = value
```

For example:

```groovy
int age = 30
```

Here:

```text
int      → data type
age      → variable
30       → value
```

Another example:

```groovy
String name = "Ashraf"
```

The variable `name` is explicitly declared as a `String`.

---

## 5. Static Typing Example

```groovy
int firstNumber = 5

println firstNumber
```

Output:

```text
5
```

Now consider:

```groovy
int firstNumber = 5

firstNumber = "Hello"
```

This is not valid because `firstNumber` was declared as an integer.

Conceptually:

```text
firstNumber
     ↓
   Integer
     ↓
     5
```

You cannot later put a String into the same statically typed variable.

```text
firstNumber
     ↓
   Integer
     ↓
  "Hello" ❌
```

---

# 6. Why is it Called Static Typing?

Because the type is explicitly specified.

```groovy
int number = 10
```

The variable is declared as an `int`.

The compiler/runtime can use that declared type when checking the program.

For example:

```groovy
int number = 10

number = 20       // ✅
number = 100      // ✅
number = "Hello"  // ❌
```

---

# 7. Dynamic Typing with `def`

Groovy provides a special keyword:

```groovy
def
```

`def` allows you to declare a variable without explicitly specifying its type.

Example:

```groovy
def value = 10
```

Instead of:

```groovy
int value = 10
```

Groovy can determine the type from the value.

---

# 8. The Important Difference

Compare these:

### Static typing

```groovy
int value = 10
```

### Dynamic typing

```groovy
def value = 10
```

With `int`:

```groovy
int value = 10

value = "Hello"   // ❌
```

With `def`:

```groovy
def value = 10

println value

value = "Hello"

println value
```

Output:

```text
10
Hello
```

The same variable can refer to different types of objects at different points in the program.

---

# 9. What Does `def` Actually Mean?

This is an **important concept for you**, especially because you're working with Groovy/Jenkins shared libraries.

When you write:

```groovy
def name = "Ashraf"
```

you are basically telling Groovy:

> "I don't want to explicitly specify the type here. Let Groovy handle it."

For example:

```groovy
def value = 10
```

Initially:

```text
value → Integer 10
```

Then:

```groovy
value = "Hello"
```

Now:

```text
value → String "Hello"
```

---

# 10. Think of `def` Like This

Imagine a box that can contain different types of objects.

```text
             ┌─────────────┐
def value →  │     10      │
             └─────────────┘
```

Later:

```text
             ┌─────────────┐
def value →  │   "Hello"   │
             └─────────────┘
```

The variable doesn't have a permanently declared type like:

```groovy
int value
```

Instead, Groovy determines the actual object/type at runtime.

---

# 11. Example from Jenkins/Groovy

You'll frequently see code like:

```groovy
def config = readYaml(file: "config.yaml")
```

Here the developer doesn't explicitly write:

```groovy
Map config = ...
```

Instead:

```groovy
def config
```

is used.

Another common example:

```groovy
def result = someFunction()
```

The function might return a:

```text
String
Map
List
Object
```

and `def` lets Groovy handle that without you having to explicitly declare the type.

This is one reason you'll see **a lot of `def` in Jenkinsfiles and Jenkins shared libraries**.

---

# 12. `def` Does NOT Mean "No Type"

This is a very important point.

Beginners sometimes think:

> `def` means the variable has no type.

That's not quite correct.

For example:

```groovy
def name = "Ashraf"
```

The value is still a `String`.

You can think of it as:

```text
def
 ↓
Groovy determines the actual type
 ↓
" Ashraf "
 ↓
String
```

So `def` means you are **not explicitly declaring the type**.

---

# 13. Static vs Dynamic Typing

| Static typing | Dynamic typing |
|---|---|
| Explicit type | Type not explicitly specified |
| Uses `int`, `String`, `boolean`, etc. | Usually uses `def` |
| Type is known from declaration | Type can be determined at runtime |
| More restrictive | More flexible |
| `int age = 30` | `def age = 30` |

### Example

Static:

```groovy
int value = 10
value = "Hello"   // ❌
```

Dynamic:

```groovy
def value = 10
value = "Hello"   // ✅
```

---

# 14. Variable Naming Rules

Groovy variable names generally follow Java-style naming rules.

A variable can contain:

- Letters
- Digits
- Underscore `_`
- `$` in some contexts

But it **should not start with a digit**.

### Valid

```groovy
def name = "Ashraf"
def firstName = "Ashraf"
def first_name = "Ashraf"
def value1 = 100
def _value = 100
```

### Invalid

```groovy
def 1value = 100
```

You cannot start a normal variable name with a number.

---

# 15. Variable Names Are Case-Sensitive

These are different variables:

```groovy
def name = "Ashraf"
def Name = "John"
def NAME = "David"
```

Groovy treats them as three different names.

```text
name ≠ Name ≠ NAME
```

For readability, normally use:

```groovy
firstName
lastName
totalAmount
buildNumber
```

rather than:

```groovy
firstname
LASTNAME
total_amount
```

Groovy projects commonly follow camelCase naming.

---

# 16. Reassigning Variables

A variable can be assigned a new value.

```groovy
def name = "Ashraf"

println name

name = "John"

println name
```

Output:

```text
Ashraf
John
```

The variable now refers to the new value.

---

# 17. Static Variable Reassignment

With a specific type:

```groovy
int number = 10

number = 20
```

This is perfectly valid.

The important point is that the **value can change**, but the declared type remains compatible.

```text
int number

10 ✅
20 ✅
50 ✅
"Hello" ❌
```

So don't confuse:

> changing the value

with:

> changing the variable's type.

---

# 18. `def` and Runtime Type

Consider:

```groovy
def value = 100

println value.getClass()
```

The actual object is an integer-like object.

Then:

```groovy
value = "Hello"

println value.getClass()
```

Now the object is a String.

Conceptually:

```text
First:

value → Integer → 100


Later:

value → String → "Hello"
```

# 20. Why `def` Is Common in Jenkins

This is especially relevant to your current Jenkins/shared-library work.

You'll frequently encounter:

```groovy
def call() {
    ...
}
```

or:

```groovy
def config = ...
```

or:

```groovy
def result = ...
```

or:

```groovy
def pipeline = ...
```

Don't get confused when you see `def`.

Usually, it simply means:

> "Groovy, determine/manage the type for me."

For example:

```groovy
def config = readJSON(file: "config.json")
```

`config` could be a Map-like object.

Then:

```groovy
def result = someMethod()
```

`result` could be whatever `someMethod()` returns.

# 22. `def` vs `String` in Jenkins Code

You might see:

```groovy
def branch = env.BRANCH_NAME
```

instead of:

```groovy
String branch = env.BRANCH_NAME
```

Both can work, but `def` is very common in Groovy because Groovy is designed to support dynamic typing.

For your current Jenkins work, **you don't need to avoid `def`**. You need to understand what it means when you encounter it.

# 24. Complete Example

```groovy
class VariableExample {

    static void main(String[] args) {

        // Static typing
        int age = 30

        println age

        // Dynamic typing
        def value = 100

        println value

        value = "Hello"

        println value
    }
}
```

Output:

```text
30
100
Hello
```
